# Model Summary Sources

How the dashboard chooses diagnostics for Model Summary / Governance / Drift.

## Priority

1. **Primary diagnostics** — existing benchmark/conformance reports (read-only; never generated by the dashboard):
   - `benchmark/conformance/reports/latest_conformance.json`
   - `benchmark/reports/latest_integrated.json`
   - `benchmark/reports/latest_stage2.json`
   - `benchmark/reports/latest.json`
2. **Governance artifact** (governance fields only):
   - `exports/model_governance_dashboard.json`
3. **Legacy fallback** (never primary when #1 exists):
   - `data/ml/model_monitoring_memory.parquet`

Implemented in `dashboard/backend/app/services/model_summary_sources.py`.

## Separation of concerns

| Concern | Source | Missing behavior |
|---|---|---|
| Latest diagnostics timestamp | conformance / integrated `generated_at` | `MISSING_DATA` |
| Classic ML metrics (PSI, macro F1, loss recall) | nested search in benchmark reports | `value=null`, `MISSING_DATA`; June legacy exposed only under `legacy_*` |
| Active / candidate / promotion | governance JSON | `GOVERNANCE_MISSING`, models `MISSING`, promotion `NO` |
| Legacy monitoring | parquet | shown as STALE / not primary when benchmark is fresh |

## Why June data can exist while July diagnostics are current

Benchmark/conformance jobs refresh July reports independently of the older
`model_monitoring_memory.parquet` writer. The dashboard previously treated that
parquet as primary, so June timestamps looked “current”. Stage 11 keeps the
parquet visible as **legacy**, but primary freshness follows July
`generated_at` from conformance/integrated reports.

## Runtime wiring (Stage 11.1)

End-to-end path:

1. `OpsDashboard.tsx` → `ResearchPipelineSection`
2. `softFetchOpsSnapshot` / `connectOps` in `dashboard/frontend/src/api/client.ts`
3. `GET /api/v1/ops/snapshot` (`dashboard/backend/app/main.py`)
4. `build_ops_snapshot` → `build_research_pipeline_snapshot`
5. `model_summary_sources.py` (`benchmark_primary_v1`)

`make runtime-stack` always **refreshes** dashboard API + Vite UI (does not adopt
a stale `:8080` / `:5173` process). UI runs `npm run dev` against `src/`, not a
frozen `dist/` bundle.

Visible Model Summary marker: `Data source: benchmark_primary_v1`.

- Does not run retrain
- Does not change the active model
- Does not mutate pipeline / execution / market-context lifecycle
- Does not change benchmark producers
- Does not generate new benchmark files

## Response shape (`model_summary_sources`)

```text
diagnostics_primary: { source_path, generated_at, freshness_status, age_hours }
governance:          { source_path, status, missing_reason }
legacy_monitoring:   { source_path, timestamp, age_days, used_as_primary: false }
```

Top Model Summary reasons:

- fresh benchmark + missing governance →
  `governance artifact missing; benchmark diagnostics current`
- stale benchmark →
  `benchmark diagnostics stale`
